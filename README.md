# Invento – Автоматизированная система учета оборудования (АСУО)

## Выполнил: Корзун Владислав Сергеевич, группа ЭФБО-01-24

## Назначение

Invento – приложение для учета, перемещения, обслуживания и списания материально-технического оборудования в организации.
Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:
* просматривать перечень оборудования в веб-браузере;
* просматривать детальную информацию о конкретной единице оборудования;
* просматривать журнал операций над оборудованием в веб-браузере;
* просматривать подробные сведения о конкретной операции;
* отслеживать текущее техническое состояние оборудования (в эксплуатации, неисправно, на складе, списано);
* находить оборудование по названию, модели и серийному номеру;
* фильтровать оборудование по категориям;
* регистрировать операции перемещения, выдачи сотрудникам, ремонта и списания;
* хранить данные между запусками приложения в JSON-файлах.

## Используемые технологии

* Python 3;
* Django 5.2 – веб-фреймворк;
* HTML – разметка веб-страниц;
* CSS и Bootstrap 5.3 – адаптивное оформление интерфейса;
* pytest – автоматизированные тесты;

## Целевая аудитория

Сотрудники ИТ-отделов, системные администраторы, завхозы и материально ответственные лица, осуществляющие контроль за наличием, состоянием и движением оборудования в организации.

## Предметная область

Основными объектами предметной области являются:
* **единица оборудования (Equipment)**;
* **сотрудник / материально ответственное лицо (Employee)**;
* **операция над оборудованием (Operation)**.

Каждая единица оборудования имеет уникальный инвентарный ID, наименование, категорию, модель, серийный номер, текущую локацию и статус.
Сотрудники закрепляются за отделами и могут выступать получателями оборудования при операциях выдачи.
Операции фиксируют жизненный цикл оборудования: передачу сотруднику, возврат на склад, передачу в ремонт или списание.

## Основные сущности

### Equipment – единица оборудования
Объект `Equipment` представляет единицу техники, подлежащую учету.
Основные атрибуты:
* `id` – уникальный идентификатор оборудования;
* `name` – наименование оборудования;
* `category` – категория техники (ПК, монитор, оргтехника и др.);
* `model` – модель устройства;
* `serial_number` – заводской серийный номер;
* `location` – текущее местонахождение (кабинет, склад, аудитория);
* `status` – состояние («в эксплуатации», «на складе», «неисправно», «списано»).

Основные методы и функции:
* `is_in_use()` – проверка, находится ли оборудование в эксплуатации;
* `is_broken()` – проверка на неисправность;
* `from_data()` – восстановление объекта из данных JSON;
* `to_data()` – сериализация объекта в словарь для JSON;
* `validate_status()` – валидация допустимости статуса;
* `find_equipment_by_id()` – поиск оборудования по ID в коллекции.

### Employee – сотрудник
Объект `Employee` представляет материально ответственное лицо или пользователя техники.
Основные атрибуты:
* `id` – уникальный идентификатор сотрудника;
* `name` – ФИО сотрудника;
* `department` – подразделение / отдел;
* `email` – адрес корпоративной почты.

Основные методы:
* `from_data()` – создание объекта из словаря JSON;
* `to_data()` – сериализация в словарь для JSON;
* `find_employee_by_id()` – поиск сотрудника по ID.

### Operation – операция с оборудованием
Объект `Operation` представляет событие изменения состояния оборудования.
Основные атрибуты:
* `id` – уникальный идентификатор операции;
* `equipment` – ссылка на объект `Equipment`;
* `employee` – ссылка на объект `Employee` (или None, если операция не привязана к сотруднику);
* `operation_type` – тип операции («выдача», «возврат», «ремонт», «списание»);
* `date` – дата фиксации операции;
* `note` – примечание / комментарий к операции;
* `is_completed` – признак завершенности операции.

Основные методы и функции:
* `complete()` – отметка операции как завершенной;
* `from_data()` – восстановление операции из JSON со связыванием объектов;
* `to_data()` – сериализация с сохранением идентификаторов связей;
* `find_operation_by_id()` – поиск операции по ID в коллекции.

## Страницы веб-интерфейса

* `/` – главная страница: описание системы и навигация (view-функция `index()`);
* `/equipment/` – список оборудования: объекты `Equipment` из `data/equipment.json` (view-функция `equipment()`);
* `/equipment/<int:equipment_id>/` – страница единицы оборудования с карточкой характеристик и статусом (view-функция `equipment_detail()`);
* `/operations/` – журнал операций: объекты `Operation` из `data/operations.json` (view-функция `operations()`);
* `/operations/<int:operation_id>/` – страница операции со связанными объектами оборудования и сотрудника (view-функция `operation_detail()`).

Если оборудование или операция с указанным идентификатором не найдены, возвращается страница с кодом ответа 404. При обращении по неизвестному URL при отключенной отладке (`DEBUG = False`) срабатывает глобальный обработчик `handler404` (`page_not_found()`).

## Основные операции

### Используется в веб-интерфейсе (ПР5)
* просмотр списка оборудования;
* просмотр детальной карточки единицы оборудования;
* просмотр журнала операций;
* просмотр детальной карточки операции;
* отображение цветовых бейджей состояний оборудования и статусов операций.

### Отложено до следующих работ
Эти операции реализованы в ПР3 и продолжают работать в консольной версии `main.py`. В веб-интерфейсе они появятся после изучения Django Forms и POST-запросов:
* добавление новой единицы оборудования;
* редактирование параметров оборудования;
* удаление оборудования;
* поиск по названию, модели и серийному номеру;
* фильтрация по категории;
* создание операции (выдача/ремонт/списание);
* завершение операции;
* добавление нового сотрудника.

## Хранение данных

Данные приложения хранятся в JSON-файлах в каталоге `data/`:
* `data/equipment.json`;
* `data/employees.json`;
* `data/operations.json`.

При загрузке данные преобразуются в объекты предметной области (`Equipment`, `Employee`, `Operation`).
Для связи операции с оборудованием и сотрудником в `operations.json` используются внешние идентификаторы `equipment_id` и `employee_id`.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3).
Отвечает за консольное интерактивное меню, сценарии ввода-вывода и управление данными.

### `invento/`
Пакет конфигурации Django-проекта:
* `settings.py` – глобальные настройки, подключенные приложения, локализация;
* `urls.py` – маршрутизация верхнего уровня и `handler404`;
* `asgi.py`, `wsgi.py` – интерфейсы взаимодействия с веб-серверами.

### `homepage/`
Django-приложение точки входа:
* `views.py` – вспомогательная функция `page()` (общий HTML-каркас с Bootstrap 5.3 CDN), view-функция `index()` и обработчик 404 `page_not_found()`;
* `urls.py` – маршрут `/`.

### `equipment/`
Django-приложение учета оборудования:
* `views.py` – view-функции `equipment()` (список) и `equipment_detail()` (карточка по ID);
* `urls.py` – маршруты `/equipment/` и `/equipment/<int:equipment_id>/`.

### `operations/`
Django-приложение учета операций:
* `views.py` – view-функции `operations()` (журнал) и `operation_detail()` (карточка по ID);
* `urls.py` – маршруты `/operations/` и `/operations/<int:operation_id>/`.

### `models/`
Классы предметной области и вспомогательные функции:
* `equipment.py` – класс `Equipment` и функция `find_equipment_by_id()`;
* `employees.py` – класс `Employee`;
* `operations.py` – класс `Operation` и функция `find_operation_by_id()`.

### `storage.py`
Модуль загрузки и сохранения данных в JSON-файлы с восстановлением связей между объектами.

### `utils.py`
Вспомогательные функции безопасного консольного ввода.

### `tests/`
Автоматизированные тесты для классов предметной области.
