## Выполнил: Корзун Владислав Сергеевич, группа ЭФБО-01-24

## 1. Назначение проекта

Invento – учебное веб-приложение для централизованного учета, перемещения, обслуживания и списания материально-технического оборудования в организации.
Проект развивается поэтапно: консольная версия приложения (ПР1–ПР3) дополнена веб-интерфейсом на Django (ПР5) и переведена на полноценную систему шаблонов Django Template Language и подключение статических файлов (ПР6).

Приложение позволяет:
* просматривать перечень оборудования в веб-браузере с выводом общего количества через фильтры;
* просматривать детальную карточку конкретной единицы оборудования;
* просматривать журнал операций над оборудованием;
* просматривать подробные сведения о конкретной операции со связанными сущностями;
* отслеживать текущее состояние оборудования (в эксплуатации, неисправно, на складе, списано);
* корректно обрабатывать запросы к несуществующим объектам с возвратом статуса HTTP 404;
* использовать централизованную навигацию по именованным URL-маршрутам;
* динамически выводить текущий год в подвале страницы средствами JavaScript;
* хранить данные между запусками приложения в JSON-файлах без преждевременного внедрения ORM.

## 4. Предметная область

В системе используются три основные сущности:
* **Единица оборудования (Equipment)** – идентификатор, название, категория, модель, серийный номер, текущая локация и состояние;
* **Сотрудник (Employee)** – идентификатор, ФИО, подразделение и корпоративная почта;
* **Операция с оборудованием (Operation)** – идентификатор, связанное оборудование, ответственный сотрудник, тип операции, дата, примечание и признак завершенности.

Для предметной области реализованы собственные Python-классы в каталоге `models/`, реляционная схема в `sql/schema.sql` и модули подключения в каталоге `db/`.
В ПР7 веб-приложение переведено на хранение и выборку данных из реляционной СУБД SQLite через SQL-запросы (`data/invento.sqlite`). Исходные данные сохранены в JSON-файлах каталога `data/`. Django ORM на данном этапе не используется.

### Основные классы:

#### `Equipment` (models/equipment.py)
* `id` – уникальный идентификатор оборудования;
* `name` – наименование оборудования;
* `category` – категория техники;
* `model` – модель устройства;
* `serial_number` – заводской серийный номер;
* `location` – текущее местонахождение;
* `status` – состояние («в эксплуатации», «на складе», «неисправно», «списано»).

Методы:
* `is_in_use()` – проверка нахождения в эксплуатации;
* `is_broken()` – проверка на неисправность;
* `from_data()` / `to_data()` – сериализация и десериализация JSON;
* `validate_status()` – проверка допустимости статуса;
* `find_equipment_by_id()` – поиск оборудования по ID в коллекции.

#### `Employee` (models/employees.py)
* `id` – уникальный идентификатор сотрудника;
* `name` – ФИО сотрудника;
* `department` – подразделение / отдел;
* `email` – адрес корпоративной почты.

Методы:
* `from_data()` / `to_data()` – сериализация и десериализация JSON;
* `find_employee_by_id()` – поиск сотрудника по ID.

#### `Operation` (models/operations.py)
* `id` – уникальный идентификатор операции;
* `equipment` – ссылка на объект `Equipment`;
* `employee` – ссылка на объект `Employee` (или None);
* `operation_type` – тип операции («выдача», «возврат», «ремонт», «списание»);
* `date` – дата фиксации операции;
* `note` – примечание / комментарий к операции;
* `is_completed` – признак завершенности операции.

Методы:
* `complete()` – отметка операции как завершенной;
* `from_data()` / `to_data()` – сериализация и десериализация со связыванием объектов;
* `find_operation_by_id()` – поиск операции по ID в коллекции.

## 5. Веб-интерфейс

Веб-часть приложения реализована на Django и работает с базой данных SQLite через чистый SQL:
Основные страницы:
* `/` – главная страница с описанием системы и ссылками на разделы;
* `/equipment/` – список оборудования из SQLite с выводом общего количества;
* `/equipment/available/` – поиск доступного оборудования (свободного от ремонта на дату) с GET-формой;
* `/equipment/<int:equipment_id>/` – карточка конкретной единицы техники из SQLite или страница 404;
* `/operations/` – журнал операций над оборудованием со связыванием данных (`JOIN`);
* `/operations/statistics/` – аналитика и статистика (`GROUP BY`, `COUNT`, `LEFT JOIN`);
* `/operations/<int:operation_id>/` – подробная информация об операции со связанными сущностями или 404.

Для формирования страниц используются **Django-шаблоны**.
Генерация HTML непосредственно в Python-коде веб-представлений **не используется**. Вспомогательная функция `page()` из ПР5 полностью удалена.
Представления подготавливают данные и передают их в шаблоны через словарь `context` с вызовом функции `render()`.

## 6. Django Template Language

Шаблоны проекта используют возможности Django Template Language (DTL).

### Базовый шаблон
Общий шаблон страниц:
`templates/base.html`
Он содержит каркас HTML-документа, метатеги viewport и charset, подключение Bootstrap 5.3 CDN, собственного CSS `homepage/css/style.css`, сквозную шапку с логотипом, блок навигации, подвал с JavaScript и блоки для переопределения в дочерних шаблонах:
* `{% block title %}` – заголовок страницы;
* `{% block content %}` – основное содержимое страницы.

Дочерние шаблоны используют наследование:
```django
{% extends "base.html" %}
```

### Включаемые шаблоны (include)
Повторяющиеся фрагменты интерфейса вынесены в отдельные шаблоны:
* `templates/includes/navigation.html` – общая навигация сайта;
* `equipment/templates/equipment/includes/equipment_card.html` – карточка единицы оборудования;
* `operations/templates/operations/includes/operation_status.html` – бейдж состояния операции.

Подключение выполняется через тег `{% include %}`:
```django
{% include "includes/navigation.html" %}
{% include "equipment/includes/equipment_card.html" %}
{% include "operations/includes/operation_status.html" %}
```

### Контекст (Context)
Представления передают данные в шаблоны через словарь контекста:
```python
context = {
    "equipment": equipment_list,
}
return render(request, "equipment/equipment_list.html", context)
```
В шаблоне данные доступны по именам ключей словаря контекста:
```django
{% for item in equipment %}
    {{ item.name }}
{% endfor %}
```

### Циклы и условия
Для формирования списков используются циклы:
```django
{% for item in equipment %}
    ...
{% empty %}
    <div class="alert alert-info">Оборудование не найдено.</div>
{% endfor %}
```

Условия используются для отображения статусов и разграничения состояний:
```django
{% if equipment %}
    ...
{% else %}
    <h1>Оборудование не найдено</h1>
{% endif %}
```

## 7. Фильтры шаблонов

В шаблонах применены стандартные фильтры Django Template Language:
* `length` – вывод количества элементов в коллекции:
  ```django
  Всего единиц: {{ equipment|length }}
  Всего записей: {{ operations|length }}
  ```
* `default` – отображение значения по умолчанию для отсутствующих или пустых полей:
  ```django
  {{ item.name|default:"Без названия" }}
  {{ op.employee.name|default:"—" }}
  {{ op.note|default:"—" }}
  ```
* `capfirst` – приведение первого символа строки к верхнему регистру:
  ```django
  {{ op.operation_type|capfirst }}
  ```

Фильтры используются исключительно для форматирования представления данных и не содержат бизнес-логики.

## 8. URL-маршрутизация и пространства имён

Для маршрутизации используются именованные маршруты и пространства имён (`app_name`):
* `homepage:index` – главная страница;
* `equipment:list` – список оборудования;
* `equipment:detail` – страница оборудования по ID (`<int:equipment_id>`);
* `operations:list` – журнал операций;

Ссылки в шаблонах формируются через тег `{% url %}`, исключая жестко заданные URL:
```django
<a href="{% url 'equipment:list' %}">Оборудование</a>
<a href="{% url 'equipment:detail' item.id %}">Подробнее</a>
<a href="{% url 'operations:detail' op.id %}">Операция №{{ op.id }}</a>
```

## 11. Хранение данных и реляционная база данных (ПР7)

В рамках ПР7 в проект внедрен полноценный слой реляционного хранения данных на базе **SQLite** и чистого **SQL** через библиотеку `sqlite3`. Django ORM на данном этапе не используется (запланирован в ПР9).

Файловая организация слоя данных:
```
Invento/
├── data/
│   ├── equipment.json       # Исходные данные оборудования
│   ├── employees.json       # Исходные данные сотрудников
│   ├── operations.json      # Исходные данные операций
│   └── invento.sqlite       # База данных SQLite
├── sql/
│   ├── schema.sql           # DDL-команды создания таблиц и связей
│   └── queries.sql          # Набор из 12 проверенных SQL-запросов
├── db/
│   ├── __init__.py
│   ├── database.py          # Подключение к SQLite (PRAGMA foreign_keys = ON)
│   └── import_json.py       # Скрипт переноса данных из JSON в SQLite
```

### 11.1. Структура таблиц базы данных

#### Таблица `equipment` (оборудование)
| Поле | Тип | Назначение / Ограничения |
|---|---|---|
| `id` | INTEGER | Первичный ключ (PRIMARY KEY) |
| `name` | TEXT | Название оборудования (NOT NULL) |
| `category` | TEXT | Категория техники (NOT NULL) |
| `model` | TEXT | Модель устройства (NOT NULL) |
| `serial_number` | TEXT | Серийный номер (NOT NULL) |
| `location` | TEXT | Текущее помещение / локация (NOT NULL) |
| `status` | TEXT | Статус (NOT NULL, DEFAULT 'в эксплуатации') |

#### Таблица `employees` (сотрудники)
| Поле | Тип | Назначение / Ограничения |
|---|---|---|
| `id` | INTEGER | Первичный ключ (PRIMARY KEY) |
| `name` | TEXT | ФИО сотрудника (NOT NULL) |
| `department` | TEXT | Подразделение (NOT NULL) |
| `email` | TEXT | Электронная почта (NOT NULL) |

#### Таблица `operations` (операции)
| Поле | Тип | Назначение / Ограничения |
|---|---|---|
| `id` | INTEGER | Первичный ключ (PRIMARY KEY) |
| `equipment_id` | INTEGER | Внешний ключ -> `equipment(id)` (NOT NULL) |
| `employee_id` | INTEGER | Внешний ключ -> `employees(id)` (NULL допустим) |
| `operation_type` | TEXT | Тип операции (NOT NULL) |
| `date` | TEXT | Дата операции в формате `YYYY-MM-DD` (NOT NULL) |
| `note` | TEXT | Примечание (NOT NULL, DEFAULT '') |
| `is_completed` | INTEGER | Признак завершения: 0 — активна, 1 — завершена (NOT NULL, DEFAULT 0) |

Связи внешних ключей:
* `operations.equipment_id` → `equipment.id`
* `operations.employee_id` → `employees.id`

### 11.2. Модули подключения и импорта (`db/`)

* **`db/database.py`**:
  Предоставляет функцию `get_connection()`, которая открывает соединение с `data/invento.sqlite` и при каждом подключении гарантированно включает контроль ссылочной целостности:
  ```python
  conn = sqlite3.connect(DB_PATH)
  conn.execute("PRAGMA foreign_keys = ON;")
  ```
* **`db/import_json.py`**:
  Скрипт переноса данных из исходных JSON-файлов в таблицы базы данных SQLite. Обеспечивает строгий порядок импорта с учетом внешних ключей (`equipment` и `employees` -> `operations`), очистку таблиц перед повторным запуском, пакетную вставку через `conn.executemany()` с параметрами `?` и управление транзакциями (`commit()` / `rollback()`).

Команда выполнения импорта:
```bash
python -m db.import_json
```

### 11.3. Набор SQL-запросов (`sql/queries.sql`)

Файл `sql/queries.sql` содержит 12 документированных запросов, проверенных в SQLite CLI и покрывающих все обязательные группы:
1. **Выборка списков (SELECT, FROM, ORDER BY):**
   * Запрос 1: Полный перечень оборудования с сортировкой по названию;
   * Запрос 2: Список сотрудников с сортировкой по отделу и ФИО.
2. **Фильтрация данных (WHERE):**
   * Запрос 3: Оборудование в эксплуатации (`status = 'в эксплуатации'`);
   * Запрос 4: Активные (незавершенные) операции (`is_completed = 0`);
   * Запрос 5: Фильтрация операций по типу и дате (`operation_type = 'выдача' AND date >= '2026-09-01'`).
3. **Соединение связанных таблиц (JOIN, подзапросы):**
   * Запрос 6: Полный журнал операций со сведениями из 3-х связанных таблиц (`operations` JOIN `equipment` LEFT JOIN `employees`);
   * Запрос 7: Поиск доступного оборудования, свободного от незавершенных ремонтов (подзапрос `NOT IN`).
4. **Агрегирующие функции (COUNT):**
   * Запрос 8: Подсчет общего количества техники и распределение по статусам;
   * Запрос 9: Подсчет общего числа активных операций.
5. **Группировка и фильтрация групп (GROUP BY, HAVING):**
   * Запрос 10: Количество оборудования по категориям (`GROUP BY category`);
   * Запрос 11: Количество операций по единицам техники (`LEFT JOIN`, `GROUP BY`);
   * Запрос 12: Сотрудники с количеством операций более 1 (`GROUP BY`, `HAVING COUNT(o.id) > 1`).

### 11.4. Интеграция с Django-представлениями

* Настройка фабрики строк: `conn.row_factory = sqlite3.Row` позволяет обращаться к полям по именам столбцов в Python-коде (`row["name"]`) и через точку в Django-шаблонах (`{{ row.name }}`);
* Безопасность: значения пользовательского ввода передаются исключительно через кортежи параметров `?` (параметризованные запросы без f-строк);
* Обработка результатов: результаты запросов передаются в шаблоны через контекст словаря `render()`;
* Реализована навигация между всеми разделами сайта («Главная», «Оборудование», «Журнал операций», «Статистика»).
